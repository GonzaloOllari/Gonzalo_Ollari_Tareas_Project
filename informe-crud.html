Introducción

Este informe documenta una aplicación web CRUD, es decir, un sistema que permite crear, leer, actualizar y eliminar (o archivar) registros almacenados en una base de datos.

El acceso está controlado: nadie puede ver ni modificar información sin haberse registrado e iniciado sesión, y las acciones disponibles dependen del rol de cada usuario.

Registro e inicio de sesión

Registro

Una persona nueva completa un formulario con nombre, correo electrónico y contraseña. El sistema valida los datos, comprueba que el correo no esté en uso y guarda la cuenta con el rol usuario por defecto. El rol admin nunca se puede elegir desde el formulario público: lo asigna un administrador existente o se carga directamente en la base de datos.

Login

El flujo de ingreso tiene estos pasos:

  1. El usuario escribe su correo y su contraseña en el formulario de login.
  2. El servidor busca la cuenta y compara la contraseña con el hash almacenado.
  3. Si los datos son correctos, crea una sesión y guarda el rol del usuario.
  4. Según el rol, el sistema muestra el panel completo (admin) o la vista de solo lectura (usuario).
  5. Si los datos son incorrectos, muestra un mensaje genérico y no revela cuál de los dos datos falló.

Roles y permisos

Cuando el rol es admin, la persona puede ver la tabla con toda la información, editar registros y archivarlos. El usuario común solo puede ingresar y consultar los datos que le corresponden.

Estos permisos se verifican en el servidor en cada petición, no solo ocultando botones en la pantalla.

Operaciones CRUD

Crear

Se agrega un registro nuevo mediante un formulario. Los datos se validan antes de guardarse.

Leer

El administrador visualiza una tabla con todos los registros. Ejemplo de cómo se vería:

Editar

El administrador modifica los datos de un registro desde un formulario con la información actual ya cargada. Se validan los cambios antes de guardarlos.

Archivar

En lugar de borrar definitivamente un registro, se marca como archivado (borrado lógico, por ejemplo con un campo archivado = 1). Así no se pierde información, se conserva el historial y el registro puede restaurarse si fue un error.

Medidas de seguridad

Contraseñas con hash

Las contraseñas nunca se guardan en texto plano. Se almacenan con un algoritmo de hash lento y con sal, como bcrypt o Argon2, de modo que aunque se filtre la base de datos no se puedan leer.

Validación en el servidor

Todos los datos que llegan se validan y se limpian en el servidor (formato de correo, longitud de la contraseña, campos obligatorios). La validación del navegador sirve para comodidad, pero no se confía en ella.

Consultas preparadas

Las consultas a la base de datos usan parámetros y no concatenan texto del usuario, lo que previene la inyección SQL.

Control de acceso por rol

Cada ruta de edición, archivo y consulta de la tabla comprueba el rol del usuario en el servidor y responde con error de acceso denegado si no es admin. Se aplica el principio de mínimo privilegio.

Sesiones seguras

La sesión se identifica con un token aleatorio, con cookies HttpOnly, Secure y SameSite, con tiempo de expiración y cierre de sesión que la destruye en el servidor.

Protección contra XSS

Todo texto que se muestra en pantalla se escapa para que un nombre o comentario malicioso no pueda ejecutar código en el navegador de otro usuario.

Protección contra CSRF

Los formularios que modifican datos incluyen un token anti-CSRF que el servidor verifica, para que otro sitio no pueda enviar acciones en nombre del administrador.

Límite de intentos de login

Se limita el número de intentos fallidos por usuario o dirección IP para frenar ataques de fuerza bruta, y los mensajes de error no revelan si el correo existe.

HTTPS y secretos fuera del código

La comunicación viaja cifrada con HTTPS. Las claves, contraseñas de la base de datos y otros secretos se guardan en variables de entorno, nunca en el código ni en el repositorio.

Conclusión

El sistema combina un CRUD completo con autenticación y autorización por roles: cualquiera puede registrarse, pero solo el administrador accede a la tabla y puede editar y archivar. Las medidas descritas protegen las credenciales, los datos y las acciones sensibles frente a los ataques más comunes.
